02 · Missing data shrinks the position

    
Nothing in the rules changed. Only what it knew.

    
No rule says "halve the size if the safety check is unavailable." A gap lowers completeness, completeness lowers evidence quality, and evidence quality sets the size. The four quality components combine as a weighted geometric mean, so a component at zero takes the whole score to zero.

03 · Independence, not agreement

  
Three voices, two opinions.

  
Three accounts quoting one thesis is one observation wearing a disguise. Every mention is checked against the ones before it. Reposts, quotes and near duplicates inside a time window are demoted to echoes, each recorded with the post it repeats and the reason it was demoted.

04 · Pre-registration

  
The commitment is sealed before the outcome is known.

  
Move a threshold, a size or a review date after the fact and you get a different decision_id. A new decision, not an edited one. Hindsight rationalisation stops being a temptation and becomes a structural impossibility. Refusals commit too: a PASS records what would have flipped it.

05 · How it works

  
Four stages, and one boundary that matters.

  
Everything before the boundary may touch the network and fail. Everything after it is a pure function of recorded inputs. Determinism and honest handling of missing data stop being features somebody remembers to add, and become properties the shape of the code enforces.


  

    

      
Stage 01

      
Collect

      
X, RSS, Telegram and the seven RYO research tools behind one adapter interface. Every response is stored under the hash of its own bytes.

      
impure · network

    


    

      
Stage 02

      
Interpret

      
Each post becomes a reading: which token, which direction, how strongly, how urgently. Produced once and frozen into the record.

      
impure · model

    


    
PURITY BOUNDARY


    

      
Stage 03

      
Decide

      
Independence check, evidence quality, verdict, size, and the falsifiers the decision commits to. No clock, no network, no model.

      
pure · replayable

    


    

      
Stage 04

      
Review

      
At the pre-registered date, each falsifier is checked against observed facts and the decision is graded against its own words.

      
pure · replayable

    

  


  
Because interpretation is frozen rather than repeated, replaying a decision proves something specific and honest: the reasoning is reproducible. It does not pretend the model would say the same thing twice. It removes the model from the question entirely.


  

    

      
The MCP transport

      
A dependency-free JSON-RPC 2.0 client over Streamable HTTP, covering the handshake the seven read-only tools need. It accepts plain JSON and server-sent events, honours the published 60-per-minute limit, and records which of the three possible result shapes each payload arrived in rather than assuming one. A test asserts that facts extracted from an MCP payload are identical to facts extracted from REST, so swapping transport touches no line of reasoning code.

    

    

      
What a live x_search returns

      
Confirmed against the real API on 28 August, and it changed the design. x_search does not hand back structured post objects. It returns the model's prose rendering of the posts plus an array of URL citations. Prose is useless as evidence, so the adapter requests a JSON schema then verifies every returned post id against the tool's own citations. A cited post is kept. An uncited post is dropped, never trusted.

      
The honest limit: the citation check proves a post exists and that the tool saw it. It does not prove the model transcribed the text or timestamp faithfully, so those fields are flagged as model-transcribed on every item.

HANKO · THE PERSONAL SEAL

      

      

        
A hanko is the seal you stamp on a document to commit to it. The mark goes on before the outcome is known, and it cannot be taken back.

        
That is what this agent does with every decision it makes. Pre-registration is a hanko. Hashing the commitment into the decision_id is a hanko. A card is stamped once at decision time, and stamped again at review, HELD or FALSIFIED, over the original.
