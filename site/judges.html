For judges

Every rubric line, and where to check it yourself.

Hanko enters Track 1 (the agent), Track 3 (exit_liquidity) and Track 2 (the workbench, the drill and the Echo Index screens). Each row below is one line of the published rubric, the place that answers it, and what to look for. Nothing here asks you to take a claim on trust: every row ends at something you can run.

Two minutes, if that is all you have

  1. The 96-second demo video: what Hanko does and the proof behind each claim. Every number on screen is from the live project.
  2. What held and what failed: a sealed SOL refusal proved wrong, plus a reproducible comparison with a simple entry rule. Open the original decision, replay it, then inspect the review.
  3. Live ledger: a run sealed every three hours with no key, committed to the repository and anchored in Bitcoin. What changed since the last run comes first, and every decision is graded 72 hours later against conditions it wrote down in advance.
  4. Try it live: exit_liquidity on BONK, $50,000. An executable venue quote, the model's own figure beside it, and the model's error, while RYO's market data is down.
  5. Failure drill: nine failures injected into the real code. Echo Index: 2,094 real posts, the measured result, and the bug the study found.
  6. From a clone, no keys: pip install -e ".[dev]" && pytest, then hanko verify-run runs/run_836b976720f63dc0.json. This is the first live ENTER (BTC, 23 Oct). It is replayed decision by decision from the committed bundle, and its manifest is anchored in Bitcoin block 972,817.

Hanko announcement on X: the project post submitted for the Social Media Award. The same link is included in the submission PDF and README.

Evidence, including the misses

The SOL refusal sealed on 23 Oct was proved wrong: its one-voice assumption no longer held when two independent voices were observed at review. The review was late, so this is a review-time observation, not a reconstructed deadline count. It invalidates that assumption; it does not prove every entry gate cleared.

Read the failure case, inspect the sealed decision, run hanko verify-run runs/run_836b976720f63dc0.json, then inspect its review and observations. The policy was not automatically retrained.

The retrospective baseline comparison uses the same recorded readings and price windows. On the first 32 eligible opportunities, both rules chose the same seven entries; their mean price return was −0.47%. All seven holding against their falsifiers did not mean all seven made money. This sample establishes no selection advantage. The script, input hashes, exclusions and every included row are published.

The baseline enters on bullish weight greater than bearish weight with at least two distinct authors, before independence filtering. Equal hypothetical 1% positions; costs omitted; overlapping observations are dependent. The baseline was specified retrospectively. Official MCP registry listing: Hanko 2.0.0.

日本語の概要

Hanko は、暗号資産をめぐる公開の発言を読み、ポジションの大きさを決めるか、判断できないと正直に答えるツールです。すべての判断は、結果が出る前に「何が起きたら間違いだったか」を書き残し、封印してビットコインのブロックに刻みます。72時間後、その条件に照らして自動で採点されます。

  • –Track 1: リポストや転送、広告を付けただけのコピーは1つの声として数えます。同じ証拠からは、モデルを呼ばずに同じ判断IDが再現されます。
  • –Track 3: exit_liquidity は、そのサイズのポジションを実際に手仕舞えるか、そのコストはいくらかを、実行可能な見積もりから答えます。RYO の応答形式に準拠し、REST と MCP の両方で呼び出せます。
  • –Track 2: /ledger は前回の実行から何が変わったかを重要な順に示します。Lighthouse のアクセシビリティは全8ページで100です。
  • –まだ証明できていないこと：RYO の市場データは2026年9月28日以降、このキーで失敗し続けています。定期実行の記録は10月24日に始まったばかりで、まだ数週間分です。詳しくは LIMITATIONS.md をご覧ください。

Track 1 (60): the agent

Track 1 rubric lines and where each is answered
Rubric lineOpenWhat to look for
Real thinking (25)--interpreter llm, tests/test_llm_interpreter.pyA model reads posts, including tokens named without cashtags, sarcasm and negation, and quotes the words its reading rests on. Code then checks every reading: a token the post never names is dropped, a quote that isn't verbatim is discarded, and an injected instruction produces nothing. The decision itself stays mechanical: evidence quality as a geometric mean, independence, the exit gate.
Cause and effect (20)/workbenchRemove one voice and the verdict flips from ENTER to PASS. The page names the rule that caused it, and shows every rule whose outcome moved, most important first.
Repeatability (10)hanko audit, hanko verify-runA decision re-derives from stored bytes to the identical id, with no cache and no model call. Each sealed run carries its own bundle and verifies from a bare clone; the scheduled workflow checks this on every run it commits. Manifests are anchored in Bitcoin through OpenTimestamps, and hanko ots-status --upgrade fetches the block attestation.
Advanced execution (5)/echo, DECISIONS.mdA reproducible study on real data that audited the agent's own echo detector. 18 recorded engineering decisions, several of them bugs found by the project's own checks.

Spotlight brief (Multi-KOL Narrative Agent): voices from X, Telegram and Bluesky; per-token stance, conviction and urgency; convergence counted on independent voices only, so a repost, forward, quote or padded copy is one voice, not two; a practice position sized under user-defined limits (Policy), with the falsifiers committed before the outcome.

What is not proven yet

In full in LIMITATIONS.md. In short: RYO's market data has failed on every live call made with this key since 2026-09-28 (a ticket is open), so live decisions run on venue facts and lack RYO's safety and technical fields. The scheduled live record started on 24 Oct, so it is weeks long, not months, and it reads posts with a word list so it can run with no key. And the first two sealed runs predate replay bundles, so they can no longer be replayed (D-17).
